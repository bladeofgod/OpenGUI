# 议题草稿：独立 Codex 插件的原生鸿蒙驱动

## 问题与已有实现

希望在本机 macOS 上，通过已授权的原生鸿蒙测试机完成截图式 GUI 操作。
fork 已有 HDC + UiTest 驱动，复用独立 Codex 插件的会话、设备锁、动作预算和
截图控制；不分发 HDC，不安装手机代理。默认 Android 路径及其视频首帧门槛保留。

鸿蒙路径使用截图和辅助布局，明确拒绝 Android 的 scrcpy 视频接口。当前真机
短流程覆盖 TYR-AL00 的观察、桌面翻页恢复及清理；API 17 的模拟覆盖不宣称为
API 17 真机验收。该提案不扩展到 WorkBuddy、DSH 或完整客户端/服务端。

## 希望维护者明确的方向

1. 是否接受独立 Codex 插件增加可选鸿蒙驱动。
2. 是否应基于当前 `main`，还是等 PR #104 的共享执行内核落地后接入。
3. 鸿蒙截图会话与 Android 视频准备采用不同能力路径是否符合项目方向。
4. 独立插件 MIT 声明与根贡献指南的 BUSL/商用授权/CLA 条款如何适用本次贡献。

可提供按功能拆分的源码、测试和通用复现说明；不附带个人或业务应用的原始
截图、账号数据和项目专属验收材料。
